      正規表現サンプル
      
      
      
        パス・クライアント IP・全文検索・ログファイルの各フィールドは正規表現に対応しています。
        マッチは大文字小文字を区別しません。ステータス（例: 500 / 4xx）と
        メソッド（例: GET）は完全一致であり、正規表現ではありません。

        書き方ガイド
        
          
          
          考え方
          
          
          
            読みたいログの 1 行をそのまま書き写し、行ごとに変わるところだけを
            「部品」に置き換えてください。これだけです。置き換えた部品に名前を付けると、
            その中身が一覧の列になります。
          
          
          
          
            
          
              ログの行
              203.0.113.5 - - [15/Jun/2026:08:01:12 +0900] "GET /a/b HTTP/1.1" 200 123
            
          
            
          
              置き換え例
              ^(?<client>\S+) \S+ \S+ \[(?<ts>[^\]]+)\] "(?<method>\S+) (?<path>\S+)[^"]*" (?<status>\d+|-) .*$
            
          
          
          
          
          
            名前は 7 つ決まっていて、ts（日時）・client（アクセス元）・
            status（ステータス）の 3 つが必須です。画面の絞り込みと集計が
            この 3 つの上に建っているので、欠けると一覧も期間もステータスも成り立ちません。
          
          
          
          
            
          ts必須。日付まで含めること
          
            
          client必須。一覧の Client 列に出る。プロキシ経由なら実クライアントをここ（client）へ取る
          
            
          status必須。- なら「記録なし」として扱う
          
            
          method任意。省くと -
          
            
          path任意。省くと -
          
            
          host任意。一覧の Remote 列（接続元）。省くと client と同じ値
          
            
          xff任意。X-Forwarded-For。Client 列には出ない（絞り込みとツールチップに使う）
          
          
          
          
          
            プロキシ経由のログで実クライアントを一覧に出したいときは、
            その値を client に取ってください。
            xff に取っても Client 列はプロキシのままです
            （組み込みの nginx 書式は末尾の X-Forwarded-For を Client 列へ
            載せますが、利用者定義ではどの値を Client にするかを自分で決めます）。
            X-Forwarded-For が 203.0.113.5, 10.0.0.1 のようにカンマで
            連なるときは、先頭だけを取る書き方
            （(?<client>[^,\s]+)）にしてください。
            取った値はそのまま入るので、こちらで切り分けることはしません。
          
          
          
          
            行の最後まで書いてください。combined の末尾には referer と
            user-agent が付きますが、そこを読む必要がなければ .*$ で
            まとめて受ければ十分です。
          
          

          
          部品
          
          
          
            クリックすると正規表現の欄に差し込みます（カーソルの位置に入ります）。
          
          

          
          日時（どれか 1 つを選ぶ）
          
          
          
            
            
            
            
            
          
          

          
          アクセス元・リクエスト・ステータス
          
          
          
            
            
            
            
            
            
          
          

          
          つなぎ・そのほか
          
          
          
            
            
            
            
            
            
          
          

          
          
            行によって出たり出なかったりする部分があるときは、そこを
            (?: と )? ではさみます。たとえば vhost
            （example.com:80 ）が付く行と付かない行が混ざるなら
            (?:\S+:\d+ )? です。
          
          
          
          
            ログの中の . [ ] (
            ) + * ? |
            $ ^ \ は、そのままだと別の意味に
            なります。文字として書きたいときは前に \ を足してください
            （. なら \.）。
          
          

          
          日時書式（日時欄）
          
          
          
            ts で取り出した文字列を、どう読むかの指定です。
            正規表現ではなく Java の日時パターンを書きます。
            上の日時の部品を選ぶと、この欄も一緒に入ります。
            正規表現を先に組み立てたいときは、空のままで構いません（その間は
            この行で試すが、取り出せた文字列をそのまま見せます）。
          
          
          
          クリックすると日時書式の欄に入ります
          
          
          
            
            
            
            
            
            
            
          
          
          
          
            ts が取り出した文字列と、この日時パターンの形は
            ぴったり合わせてください。区切りが違うだけでも読めません。
            日付を含まない書式（時刻だけ）は、日をまたいだときに並べられないため使えません。
          
          
          
          
            オフセット（+0900 など）がない書式は UTC として読みます。
            組み込み書式がオフセットのないログを +0000 として扱うのと同じで、
            画面にはログに書かれたままの時刻が出ます。
          
          

          
          うまくいかないとき
          
          
          
            読みたいログを 1 行そのまま「試すログの行」に貼り、この行で試すを
            押してください。各項目に何が取れたか、一致しないときはどこを直せばよいかが出ます
            （登録はされません）。よくある原因は次の 3 つです。
          
          
          
            
            
          • 
              行の全部を書いていない。
              ^ から $ まで、行の最初から最後までが一致する形にします。
              末尾の referer と user-agent を読まないときも .*$ で受けてください。
            
            • 
            
          • 
              空白の数が違う。
              桁を揃えるログでは空白が 1 個とは限りません。
              空白 1 個ではなく空白 1 個以上（ +）を使ってください。
            
            • 
            
          • 
              日時の形が合っていない。
              [ ] を ts の中に含めるかどうかで、
              日時書式の書き方が変わります。上の部品は角括弧を外側に置いています。
            
            • 
          
          

          
          読めない形式
          
          
            
            
          • 
              1 エントリが 2 行以上になる形式。
              一致しなかった行は読み飛ばし、件数と例を画面に出します。
            
            • 
            
          • 
              (a+)+ のように繰り返しを入れ子にした書き方。
              照合が急激に重くなるため、行の長さに見合わない照合は打ち切って、読み込み全体が
              失敗します（画面が固まったままにはなりません）。
            
            • 
            
          • 
              (?x)（空白を無視する書き方）。
              コメントの中に書いたグループを、アプリ側が「ある」と数えてしまいます。
            
            • 
          
          

          
          登録したあと
          
          
          
            書式のプルダウンから選んで 読み込み を押すと、その書式で読み込みます
            （自動判定に任せることもできます）。alv は解析結果をメモリに持つので、
            書式を直したら読み込み直すだけで反映されます。
