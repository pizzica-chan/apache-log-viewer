        ログ書式の管理
        
      
        
        保存先: 読み込み中...
      
        
      
        
        組み込みの書式のほうが読み込みは速いです。
        combined や nginx など、組み込みで問題なく読めるログなら、書式のプルダウンから
        組み込みを選んでください。この画面は、組み込みだけでは読めない並びを
        正規表現で定義するときに使います。登録した書式はプルダウンに並び、
        自動判定の候補にもなります。
      
        

      
          
      
          登録した書式はまだありません。
          
      
          

      
          
        
          新しい書式を登録
          
        
        
          
          編集中は id を変えられません。別の書式として登録したいときは
          「入力をクリア」を押してください。
        
          
        
        
        
        
        
          
          
          
          
        
          
        
          
      
          

      
          
        書き方ガイド
        
          
          
          
          
          考え方
          
          
          
            まず、読みたいログの 1 行を正規表現の欄にそのまま書き写します。
            次に、行によって変わる部分（IP や日時など）だけを、下の「部品」ボタンが
            挿入する正規表現に置き換えます（その部分の文字列を消し、パターンを書くイメージです）。
            部品には ts などの名前が付いており、行に一致したときに取り出した値が一覧の列になります。
          
          
          
          
            
          
              ログの行
              203.0.113.5 - - [15/Jun/2026:08:01:12 +0900] "GET /a/b HTTP/1.1" 200 123
            
          
            
          
              置き換え例
              ^(?<client>\S+) \S+ \S+ \[(?<ts>[^\]]+)\] "(?<method>\S+) (?<path>\S+)[^"]*" (?<status>\d+|-) .*$
            
          
          
          
          
          

          
          
          
          取り出す項目（7 つ）
          
          
          
            必須は ts（日時）・client（アクセス元）・status（ステータス）の 3 つだけです。
            並べ替え・期間・Client IP・ステータスでの絞り込みは、いずれもこの 3 つを取り出せることが前提です。
          
          
          
          
            
          ts必須。日付まで含めること
          
            
          client必須。一覧の Client 列に出す IP をここで取る
          
            
          status必須。- なら「記録なし」として扱う
          
            
          method任意。省くと -
          
            
          path任意。省くと -
          
            
          host任意。一覧の Remote 列（接続元）。省くと client と同じ値
          
            
          xff任意。X-Forwarded-For 全体を別名で残す（Client 列には出ない）
          
          
          
          
          

          
          
          
          Client 列とプロキシ（nginx など）
          
          
          
            一覧の Client 列に表示されるのは、正規表現で名前
            client を付けて取り出した値だけです。
            xff など別の名前に取った値は Client 列には出ません。
          
          
          
          
            プロキシの後ろに Apache へ載るログ（nginx など）では、
            行の先頭の IP がプロキシで、利用者の IP が行末付近の X-Forwarded-For に
            書いてあることがよくあります。Client 列に利用者の IP を出したいときは、
            先頭の IP ではなく X-Forwarded-For 側の IP を client として正規表現を書いてください。
            先頭 IP を client にしたままだと、Client 列はプロキシの IP のままです。
          
          
          
          
            組み込み書式の nginx は、X-Forwarded-For を Client 列に載せるよう
            あらかじめ決めています。利用者定義では、どの部分を client にするか自分で決めます。
            X-Forwarded-For が 203.0.113.5, 10.0.0.1 のようにカンマで複数 IP
            並んでいるとき、Client 列に左の IP（203.0.113.5）だけ出したい場合は、
            正規表現で先頭の IP だけを client に取ってください（例:
            (?<client>[^,\s]+)）。
            このアプリは取り出したあとカンマ以降を切り捨てないので、カンマごと
            client に入れると Client 列にもそのまま全部出ます。
          
          
          
          
            次の表は説明用の IP 例です。同じような行でも、
            どこに client / host / xff を付けるか
            （または組み込み書式を選ぶか）で一覧の列が変わります。
            xff は Client / Remote 列には出ず、IP 絞り込みと行のツールチップに使います。

          部品（正規表現のひな形）
          
          
          
            クリックすると正規表現の欄に差し込みます（カーソルの位置に入ります）。
          
          

          
          日時（どれか 1 つを選ぶ）
          
          
          
            
            
            
            
            
          
          

          
          アクセス元・リクエスト・ステータス
          
          
          
            
            
            
            
            
            
          
          

          
          つなぎ・そのほか
          
          
          
            
            
            
            
            
            
          
          

          
          
            行によって出たり出なかったりする部分があるときは、そこを
            (?: と )? ではさみます。たとえば vhost
            （example.com:80 ）が付く行と付かない行が混ざるなら
            (?:\S+:\d+ )? です。
          
          
          
          
            ログの中の . [ ] (
            ) + * ? |
            $ ^ \ は、そのままだと別の意味になります。
            文字として書きたいときは前に \ を足してください
            （. なら \.）。
          
          
          
          

          
          
          
          日時書式（日時欄）
          
          
          
            ts で取り出した文字列を、どう読むかの指定です。
            正規表現ではなく Java の日時パターンを書きます。
            上の日時の部品を選ぶと、この欄も一緒に入ります。
            正規表現を先に組み立てたいときは、空のままで構いません（その間は
            この行で試す が、取り出せた文字列をそのまま見せます）。
          
          
          
          クリックすると日時書式の欄に入ります
          
          
          
            
            
            
            
            
            
            
          
          
          
          
            ts が取り出した文字列と、この日時パターンの形はぴったり合わせてください。
            区切りが違うだけでも読めません。日付を含まない書式（時刻だけ）は、
            日をまたいだときに並べられないため使えません。
          
          
          
          
            オフセット（+0900 など）がない書式は UTC として読みます。
            組み込み書式がオフセットのないログを +0000 として扱うのと同じで、
            画面にはログに書かれたままの時刻が出ます。
          
          
          
          

          
          
          
          うまくいかないとき
          
          
          
            読みたいログを 1 行そのまま「試すログの行」に貼り、
            この行で試す を押してください。
            各項目に何が取れたか、一致しないときはどこを直せばよいかが出ます
            （登録はされません）。よくある原因は次の 3 つです。
          
          
          
            
            
          • 
              行の全部を書いていない
              ^ から $ まで、行の最初から最後までが一致する形にします。
              末尾の referer と user-agent を読まないときも .*$ で受けてください。
            
            • 
            
          • 
              空白の数が違う
              桁を揃えるログでは空白が 1 個とは限りません。
              空白 1 個ではなく空白 1 個以上（ +）を使ってください。
            
            • 
            
          • 
              日時の形が合っていない
              [ ] を ts の中に含めるかどうかで、
              日時書式の書き方が変わります。上の部品は角括弧を外側に置いています。
            
            • 
          
          
          
          

          
          
          
          読めない形式
          
          
            
            
          • 
              1 エントリが 2 行以上になる形式
              一致しなかった行は読み飛ばし、件数と例を画面に出します。
            
            • 
            
          • 
              (a+)+ のように繰り返しを入れ子にした書き方
              照合が急激に重くなるため、行の長さに見合わない照合は打ち切って、読み込み全体が
              失敗します（画面が固まったままにはなりません）。
            
            • 
            
          • 
              (?x)（空白を無視する書き方）
              コメントの中に書いたグループを、アプリ側が「ある」と数えてしまいます。
            
            • 
          
          
          
          

          
          
          
          登録したあと
          
          
          
            書式のプルダウンから選んで 読み込み を押すと、その書式で読み込みます
            （自動判定に任せることもできます）。alv は解析結果をメモリに持つので、
            書式を直したら読み込み直すだけで反映されます。
